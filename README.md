# Localdeck

ローカルアプリの起動・停止、HTTPSのURL、ログをまとめるダッシュボードです。
状態とカテゴリで絞り込み、検索、ドラッグまたはメニューでの並べ替えができます。
ライト／ダークテーマ、キーボード操作（⌘K / Ctrl+K）にも対応します。

## 必要環境

- macOS
- Node.js 22.13以上
- `caddy` コマンド

## セットアップ

通常のTerminalまたはiTermで実行します。Codex配下から本体を起動すると、管理対象アプリもファイルシステムの制限を継承するため、起動・再起動は通常のターミナルで行ってください。

```sh
npm install
npm start
```

起動後に <https://apps.localhost> を開きます。Caddy、管理画面、登録済みルートはまとめて起動・同期されます。
管理画面は起動元とは別セッションで動作するため、ターミナルやブラウザを閉じても停止しません。

```sh
npm run local:status
npm run local:restart
npm run local:stop
```

## アプリの登録

設定画面には基本設定、起動とポート、バックエンド、自動起動・停止の4つのタブがあります。

- フォルダ、起動コマンド、ドメイン、固定／自動ポートを登録できます。
- 環境変数は `NAME=value` を1行ずつ指定します。値はSQLiteに保存されます。秘密の値はLocaldeckを起動する環境から渡し、必要な環境変数名だけを登録してください。
- コマンドは引用符で空白を含む引数をまとめられます。シェル展開は行いません。複数コマンドの連結は起動スクリプトにまとめてください。
- メインのほかに最大12個のバックエンドを登録できます。バックエンドの待受を順に確認してからメインを起動します。途中で失敗すると、その操作で起動したプロセスを停止します。
- 稼働中の起動設定変更と登録削除は拒否します。先に停止してください。同じプロセスをlaunchdなど別のSupervisorと同時に管理しないでください。

既存の登録は固定ポート・自動起動なし・自動停止なしとして引き継ぎます。
カテゴリ、並び順、起動エラーもSQLiteに保存されます。

### 動的ポート

自動ポートは以前のポートが空いていれば再利用し、使用中なら別の空きポートを選びます。
アプリ側も指定されたポートを使用する必要があります。コマンドと環境変数には次の置換が使えます。

| 指定 | 意味 |
| --- | --- |
| `{port}` | メインの割り当てポート |
| `{backendPort:api}` | IDが `api` のバックエンドの割り当てポート |

Viteの例:

```sh
npm run dev -- --port {port} --strictPort
```

APIの接続先を環境変数で渡す例:

```text
API_URL=http://127.0.0.1:{backendPort:api}
```

ポート用の環境変数名もアプリ・バックエンドごとに指定できます。固定ポートの既存登録では空欄のまま環境を引き継げます。転送先は割り当て結果と一緒に保存し、Caddyへ反映します。
アプリの起動成功は待受ポートとプロセスグループで確認します。アプリ内部のAPI接続や業務処理の正常性までは保証しません。

### アクセス時の起動

「アクセス時に起動」を有効にすると、CaddyからLocaldeckのゲートウェイへリクエストを転送します。
停止中なら起動完了を待ってから、登録したアプリへ転送します。同時アクセスは1回の起動を共有します。
HTTPの本文・ストリーミング・WebSocketに対応します。HTTPSの終端はCaddyです。

### 自動停止と起動維持

自動停止はアプリごとの明示的な設定です。初期値の0分は無効です。
ローカルドメイン経由の接続中のリクエストやWebSocket、「起動を維持」が有効なアプリは停止しません。転送先ポートへの直接アクセスは計測対象外です。

バックグラウンド処理を行うアプリでは、メインの転送先から到達できる処理状態の確認パスを指定してください。
確認先は、停止してよいときだけ次を返す必要があります。

```json
{"busy": false}
```

`busy: true`、応答失敗、未対応のレスポンスでは停止しません。
バックグラウンド処理のないツールでは「バックグラウンド処理・定期実行を行わない」を明示すると、アクセスの有無だけで停止できます。
定期実行を担うアプリでは自動停止を無効にしてください。Localdeckはそのアプリの将来のスケジュールを把握しません。

## ログとアイコン

通常の監視はTCP接続だけを確認します。PIDと稼働時間は詳細画面を開いたとき、または「情報を再取得」を押したときだけ調べます。詳細画面を開いたままでも定期調査は行いません。

プロセス方式の標準出力・標準エラーは `logs/apps/<app-id>.log`、バックエンドは `logs/apps/<app-id>__<backend-id>.log` に保存します。
カードのログボタンから、末尾128KBの閲覧、1秒ごとの追従、コピーができます。

アイコンは作業フォルダ内の `public/`、`web/public/`、`apps/web/public/` などのfaviconから読み込みます。
アイコン取得ではアプリを起動しません。見つからない場合はアプリ名の頭文字を表示します。

## ローカルファイル

次の実行時ファイルはGit管理外です。

```text
state/localdeck.sqlite
state/*.pid
logs/apps/*.log
launchd/*.plist
```

## 開発

```sh
npm test
npm run lint
npm run typecheck
```

テストは一時DB、モック、検証用プロセスで実行し、登録済みアプリや稼働中のCaddyは操作しません。
`npm run build` は管理画面を `dist-local/`、TypeScript製の管理サーバーを `dist-server/` へ出力します。
稼働中の画面に影響を与えずUIを確認する場合は別の出力先を指定できます。

```sh
npx vite build --outDir /tmp/localdeck-ui-preview/dist
node tests/ui-preview.mjs /tmp/localdeck-ui-preview/dist
```

表示されたURLはメモリ上のサンプルデータだけを操作するUI検証用サーバーです。終了すると変更は失われます。
